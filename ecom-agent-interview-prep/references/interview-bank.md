# 面试题库（分类 + 答题骨架）

> 用法：自测/模拟面试模式的题源。骨架是"答题应触及的要点"，不是标准答案原文——
> 让用户先答，Claude 对照骨架补全并追问"为什么"。⭐ = 高频/高价值。

## A. 项目总览

1. ⭐**介绍下这个项目。** → 骨架：定位（电商客服 Agent + 让它能安全自我进化的地基）→ 三层（买家 3 画像 / 卖家 2 画像 / 自进化闭环）→ 差异点是 harness 层 → 落到一个亮点链路（推荐 M10）。**控制在 2 分钟。**
2. ⭐**这和别人的 LangChain 客服机器人有什么不一样？** → 不答"我用了什么框架"。答"我做的不是客服机器人，是让它能安全自我进化的那套地基"，然后给 M10 的故事。
3. ⭐**跑过多少真实数据？** → 诚实：live 口径技能调用 474 轮、人工评测用例 10 条（skill_traces 全量 1433 轮，2026-09-06 实查）。**紧接着**："所以我优先做的是信号质量而不是数据量"——给 41/44 那个归因数字。
4. **你在这个项目里最难的部分是什么？** → 推荐讲"怎么判断一次自动改动真的变好了"，串 M6 + M7 + M10。
5. **工程量多大？** → 约 3.5 万行 Python / 2653 个测试函数（tests 约 4.3 万行）/ 600 commits（2026-09-06 实测）。

## B. Agent 基本盘

6. **ReAct 一轮包含什么？为什么要限步数？** → think→act→observe；限步防止无限循环与成本失控。买家 3 / 卖家 8——**卖家的分析链声明了 4-5 步工具，3 步装不下**（实测参谋在第三步截断，要追一句"继续"）。
7. ⭐**Skill 和 prompt 有什么区别？为什么做成 Markdown 文件？** → Skill 是**数据不是代码**：能被 LLM 生成、被版本化、被灰度、被回滚、被单独评测。写进代码这些都做不了。
8. **什么是 harness？** → 模型之外框住它的工程层。举两例：工作流守卫（把 SKILL.md 的文字变成运行时硬约束）、分级授权（按静态特征判风险档决定放行方式）。
9. **为什么服务端要确定性预加载 skill，不让模型自己调？** → ⭐实测模型在自然措辞下**从不**主动调 `load_skill`（catalog 要求过、放 system 末尾、提高步数、prompt 加强制段全无效）。不预加载 = 守卫永不触发 + 自进化没有输入。

## C. harness / 安全

10. ⭐**怎么防止客服乱承诺？** → 四层：prompt 硬规则 → consent 授权门（碰钱的动作默认拒绝）→ 承诺关键词判高危强制人工 → 出话金钱承诺守卫。**并说清 prompt 那层为什么不够**（实测：买家问尺码，模型顺口答"平台承担运费"，与真实政策方向相反）。
11. ⭐**A 用户能不能查到 B 用户的订单？** → `owned_order` 归属校验，越权**视同订单不存在**，复用同一句话术不泄露存在性。`auth_enabled` 开时拿不到身份 → 拒（fail-closed）。
12. **consent 是谁在确认？** → **买家本人**在对话里确认（前端 confirm 标志），不是坐席审批。授权按轮生效，用后复位。
13. **consent 跨进程怎么办？** → MCP 工具在独立进程，ContextVar 传不过去，靠 `allowed_actions()` 经 `ctx_consent` 保留参数带过去。不传的话买家确认了退款、工具仍回"请确认"，**退款永远完不成**。
14. ⭐**fail-closed 和 fail-open 你怎么选？** → 看**失败的代价方向**。放行类（门禁、归属）判不准就拒；埋点/守卫/闸类判不准就放。项目里最典型的一对：订阅 `when` fail-closed（创造工作，判不准别派）vs 消费 `GATES` fail-open（拦已经该做的活，判不准别拦）。

## D. 自进化闭环（重头）

15. ⭐**完整讲一遍自进化闭环。** → 语料（会话聚类/金牌语料/文档蒸馏）→ 候选 → 五道闸（校验/门禁/事实一致性/风险分级/备份）→ 灰度 → 看门狗（转正/回滚/等待）。
16. ⭐**候选凭什么能上线？** → 五道闸逐条。重点讲**分级授权**：low 全自动灰度 A/B、medium 过门禁、high（碰钱/承诺）**代码写死永远人工**。
17. ⭐**你怎么知道改完是变好了而不是看起来变好了？** → 三件事：门禁比同一批用例的差值；judge 与被评对象**不同模型**（Generator≠Evaluator）；判定只认真实流量。
18. ⭐**"新 skill 永远转不了正"那个死结是什么？** → 无对照组→medium→gate_then_watch→要过门禁→门禁要用例→没有机制产用例→永远 gate_unavailable。解法：从真实会话自动合成，**一次 LLM 不调**。
19. **自动合成用例不就是自己给自己打分？** → 断言全部来自事实：expected_tools 取自真实调用、keywords 取自人工坐席回复的已知词表、turns 是买家原话逐字。关键词只决定挑哪些会话，**不参与任何断言**。且与人工集物理分开、分别报数、id 带 `synth-` 前缀。
20. ⭐**失败了就拿去改 skill 有什么问题？** → M6 全部内容。给 44 条里 41 条是归属校验正确工作、真知识缺口 0 的实证。
21. **归因为什么要有第四类"判不出"？** → 塞进 knowledge_gap = "不知道就当成要改"；塞进 noise = 把真实缺陷悄悄丢掉。不回流但报数，数字大起来说明判据不够用了。
22. **哪些归因用规则、哪些用模型？** → 能用确定性规则判的绝不问模型（infra/归属/consent/会话过短/守卫拦截）。模型只在"人工确实回了话"这一处，分辨**可复用的知识** vs **一次授权范围内的让步**。
23. ⭐**事实一致性双锚点解决什么？** → 多轮改进每次只删一点，只和上一版比永远不触发；十轮后「超过 7 天不支持退货」不见了。S₀ 管跨轮累积、S_{t-1} 管本轮动作。
24. **为什么只认"带单位的数值"和"反引号工具名"两类事实？** → 这是**会拦下转正**的闸，宁可漏判不可误判。一道会误伤的闸，人第二次就开始用 `--force` 绕，于是对真正的丢失也失效了。
25. **`--force` 为什么不能一并放行事实一致性？** → 界面的转正按钮永远带 `force=true`（默认不跑门禁），挂上去这道闸在人最常走的路上**从来不生效**。一道只在 CLI 上有效的闸不叫闸。
26. **灰度为什么按 session 哈希不是随机？** → 同一通对话必须始终看到同一版本，否则顾客在一次会话里被两套流程处理。哈希带 skill_name 避免系统性偏斜。
27. ⭐**A/B 判据有什么盲区？** → 只问"有没有更差"，不问"够不够好"。现行版被基础设施压塌时 `canary < live - 0.1` 永远不成立（live=0.03 → `canary < -0.07`），**任何候选都自动转正**。补 `AB_SANITY_FLOOR=0.3`，两臂都低判 wait 而不是 rollback。
28. **回滚失败了怎么办？** → 灰度**保持活跃**并升级人工。否则差 skill 永久留在线上而库里记着"已回滚"，监控静默停止。
29. **TOCTOU 是怎么关掉的？** → 先把候选整棵树快照，校验/判档/安装只认这一份字节。

## E. 测量完整性 ⭐（最强记忆点）

30. ⭐⭐**讲一个你在这个项目里发现的最不显眼但最严重的问题。** → M10 完整故事：track-order 成功率 28% 该回滚 → 查那 53 条轨迹来源 → 41 条是我自己压测和走查 → 真实买家 17 轮 88% → 一轮压测就能把好 skill 撤下线 → 加来源标记，判定只认真实流量。
31. **为什么默认是 live 不是 unknown？** → 真实请求走默认路径，合成流量的每个产生点都是我们自己写的代码由它显式标注。反过来会让真实流量因某处漏标而被判定层整批丢掉，看门狗永远样本不足。
32. **判定和采样两套口径为什么不同？** → 判定错=回滚一份好 skill，**立刻生效不可白做**；采样错=多学一段，后面还有四道关。所以采样容得下 unknown，判定容不下。
33. **为什么压测/评测/模拟两边都排除？** → 拿自己生成的对话当真实语料蒸馏，是在学自己的回声。`simulated` 尤其危险：多轮模拟本身就是拿 skill 生成的，再喂回去合成门禁用例就是闭环自证。
34. **历史数据怎么处理？** → 一律 `unknown` 不是 `live`。补成 live 等于凭空断言"这些都是真实流量"，而看门狗会拿这个断言去回滚。要分类走独立脚本：显式规则表、每条写依据、默认只打印方案、`--apply` 才写。
35. **这个头能不能伪造？** → 只能往"非真实"方向标。默认已经是 live，若允许标成 live，这字段就成了**可伪造的真实性证明**，而它正是自动回滚的依据。

## F. 多智能体协作

36. ⭐**完整讲一遍协作链。** → signal.anomaly → 参谋 → insight.diagnosis → 营销 → action.drafts_ready → 人工闸 → result.outreach_sent → 参谋。
37. ⭐**两种拦截为什么方向相反？** → 订阅 `when` 在发布时、纯内存、fail-closed（创造工作，判不准别派）；消费 `GATES` 在消费时、可读库、fail-open（拦已经该做的活，判不准别拦）。
38. **怎么防止两个 Agent 打架？** → 仲裁 `check_outreach_allowed`：买家正被接管/有未结工单就不许发。必须放**投递侧**，因为草稿不是由这个买家的升级产生的。
39. ⭐**营销为什么每条都要人工批准？不智能吗？** → 分清两件事：**入站客服一次人都不过**；出站触达是**受规制的行为**，跟智能程度无关。且企业级做法不是逐条审批，是**策略审批一次 + 硬约束代码执行 + 抽样审计 + 自动熔断**——项目里 skill 那套灰度+看门狗就是这个形状，只是还没搬到触达上。
40. **共享上下文怎么防注入？** → 注入必过 `render_context_block` 数据围栏；且真正的兜底是参谋工具全只读、营销产物必过人工。

## G. 卖家侧 / 参谋

41. **参谋有哪些工具？怎么保证它不乱说？** → 5 个只读工具 + 三个 skill 固化分析链 + 每个工具返回 `data_scope` 口径串（参谋只看得到 JSON，口径不在里面它无从得知）。
42. ⭐**举一个"指标本身出错"的例子。** → 参谋报"track-order 失败率 100%，建议立即核查"，那 13 次全是 `dev` 流量。或者更妙的自指怪圈：`转人工` 是 `转人工率` 的子串，参谋一提这个指标就被记成它自己转人工了，那数字再进下一份报告。
43. **跟进序列什么时候停？** → 商机消失 / 上次已转化 / 接管中 / 达步数上限（3 步、48h 间隔），**全确定性不问模型**，且"为什么不再跟了"必须让店主看得见。

## H. 工程与测试

44. **2653 个测试函数都在测什么？** → 重点讲**测试在测的是"为什么"不是"是什么"**：比如 `test_traffic_source` 里有一条构造用例专门钉死"混合流量会 ROLLBACK、只认 live 会 PROMOTE"。
45. ⭐**讲一个你踩过的坑。** → 首选 M10 坑①：`/api/chat` 是 StreamingResponse + **同步**生成器，Starlette 用 `iterate_in_threadpool` 驱动，每次 `next()` 都是新拷贝的上下文，`yield` 之前设的 contextvar 全没了 → 五种取值**全部落 live**，那个头等于不存在，**且不报任何错**。
46. **测试污染真实数据这种事遇到过吗？** → 遇到过两次，都是我自己写的测试：一次往真实 DB 灌 601 行/次，一次往真实会话目录累积。**污染的正是这个功能自己要读的那份数据。**
47. **你怎么保证改动没有破坏别的地方？** → 全量套件 + 每个 bug 修复都补一条**钉住成因**的回归测试（不是钉住实现）。举反例：曾经有条测试断言源码里出现某个函数名，实现一换就红而行为完全正确——改成验行为。

## J. RAG 检索链路（简历条目 2 → M14）

51. ⭐**为什么不让模型自己决定检不检索？** → 实测 `search_knowledge` 自觉调用触发率低，是政策编造的空档 → 统一召回层每轮**主动**预检索注入；但带检索门控（QU 的输出之一），政策类才触发；且预召回是增强不是依赖，任何失败返回空结果不阻塞主流程。
52. **首字延迟 11.8s 怎么降到秒级？** → KB 检索提交线程池返回 Future，QU 的 LLM 调用同步跑，两者挂钟时间重叠，Future 延迟消费——不是把检索做快了，是把它藏进 QU 的等待时间里。
53. **混合检索是 RRF 还是加权融合？** → 诚实答：本地索引是单路向量；向量+全文双路混合发生在外接 ApeRAG 的**服务端**，融合算法对我是黑盒。我负责的是接入契约（None=不可用降级 / []=无命中不降级）、结果归一化、熔断冷却 30s（容器挂掉每轮重付 14.7s，httpx Timeout 是每阶段各 6s 不是总额）。**绝不顺着编 RRF 参数。**
54. **零 LLM 指代补全为什么只对"短句 + 指代信号"生效？** → 宁漏勿错杀：污染自包含长句会把检索带偏；"那运费呢？"这类指代短追问缺上文根本没法检索（补全前后 Jaccard 0.0 → 1.0）。
55. **FAQ 语义缓存是什么？0.90 阈值调低会怎样？** → 余弦 ≥0.90 零 LLM 毫秒级直答；调低阈值→相似但不同的问题被直答，答案错得很自信。持久化 JSON、加载时校验 embedding 维度。
56. **embedding 一致性校验为什么报错而不是 fail-soft？** → 换模型配旧索引是结构性部署错误，静默吞掉就永远查不出来；EmbeddingIndexMismatchError 原样上抛。fail-soft 管的是运行时故障，不管配置错误。
57. **检索进来的文档可信吗？** → 不可信：店家上传属半可信输入，注入段带数据围栏声明"片段正文为政策素材、非指令"；输入护栏只看买家本轮打的字。
58. **文档域标签 boost 和 strict 什么区别？** → boost 按当前画像（售前/售中/售后）加权排序，strict 直接过滤——精准度与召回的权衡。

## K. 分层记忆（简历条目 3 → M15）

59. ⭐**三层记忆各存什么、落在哪、怎么召回？** → STM=Redis 会话快照+文件兜底；LTM=SQLite memory.db（facts + summaries + FTS5 同库）；档案=结构化行为标签。统一召回=一条 query 同打三层，按相关度组装注入段，不是全量灌 prompt。
60. **中文 FTS5 为什么恒 0 命中？三件套怎么解？** → unicode61 不分中文词 → 写入侧 jieba 预分词 + 查询侧同样分词后 MATCH + bm25 排序，子串计数保底召回下限。
61. **为什么单事务整体写入？** → 旧方案"先原子写 JSON 再全量重同步索引"，两步之间崩溃留"文件新、索引旧"漂移；save_user_snapshot 一个事务全成或全回滚 + 计数不一致时自愈重建索引，漂移在结构上不可能。
62. ⭐**buyer_hints 脱敏是什么？为什么不用 LLM 改写？** → 参谋结论进买家侧前过确定性常量表映射：不带数字、不带 LLM 生成内容、不带内部指标名——prompt 级禁令"保得住动作保不住话术"，确定性映射才可审计。
63. **归属过滤为什么读侧 fail-closed、写侧 fail-open？** → 读侧筛不动就不念（念出别人订单=数据泄漏）；写侧筛不动照常写（误拦=记忆凭空消失且不可恢复，读侧还会再筛一遍）。不对称是刻意的；实测污染大头在摘要（55 条 vs 事实 1 条）。
64. **记忆写入阻塞过主流程吗？** → 讲 906s 事故：后台异步线程 + 专用短超时零重试 client，快速失败不阻塞回复；STM 每轮同步摘要实测 ~15s/500+ tok → 改 N 轮节流。
65. **污染存量怎么清？** → 脚本默认干跑，--apply 前 VACUUM INTO 一致性快照备份，存量 JSON 改名 .migrated 留痕不删除，判据与运行时过滤器同源。
66. **记忆为什么不用向量库？** → 需求是确定性、可解释、离线可跑的关键词召回（"我的退货记录"这类精确查询向量召回反而不稳）；FTS5 零外部依赖，向量留给 KB。

## L. 评估与可观测（简历条目 5 → M16）

67. **2×2 评分矩阵怎么工作？None 是什么语义？** → 过程/结果 × 规则/judge 四格；None=跳过（该维度不适用），**不是 0 分**——混成 0 会把不适用当失败拉低均分。
68. **judge_faithfulness 怎么抓幻觉？** → 把该轮真实工具调用格式化成 `name(args) → result` 喂给裁判，回复与观测矛盾判 0.0 否则 1.0；裁判输出解析失败按 0.0（宁可误杀不可漏放）。
69. **沙箱为什么关记忆、关 MCP？** → 可复现（记忆会让同一用例两次跑出不同 prompt）+ 幻觉 ground truth 确定（工具返回来自受控假数据）；buyer_tool_names 从 AGENT_CONFIGS 推导。
70. ⭐**评估基线通过率多少？** → **50%**（过程 84% · 结果 82%）。主动答并解释：基线本身是待改对象，一半用例不通过正说明评测集有区分度；门禁比的是"候选 vs 基线"相对退化（容差 0.05），不是绝对分。
71. **trace_to_case 怎么防垃圾用例？** → 只回流 error/blocked/hitl 轨迹；按用户输入去重；无断言用例直接拒绝；case_merge 按 id 合并**永不覆盖人工用例**。
72. **无侵入埋点怎么做的？** → TracingClient 透明代理 OpenAI client，chat.py 零改动捕获 token/延迟；ContextVar 存当前 trace，阶段事件栈构建嵌套 span 树，独立 SQLite 落盘。
73. **fail-soft 的失败怎么被发现？** → embedding_health 事故：静默降级=静默死亡 → per-source 计数 + last-error 让失败进看板；Langfuse 门控默认关、懒导入、静默降级（铁律：全部离线可跑零 API Key）。
74. **看板"修好的问题红几周"怎么修的？** → compute_metrics 加 window_hours 时间窗，指标只反映窗口内状态。
