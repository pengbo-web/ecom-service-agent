# 确认流安全修复说明(2 P0 + 4 P1)

> 来龙去脉:对标开源项目 Customer-Agent 后做了一次架构自查(独立体检代理),挖出 13 个真问题。本批修复其中优先级最高的两个 P0(都在"确认后再执行不可逆动作"这条旗舰安全流上)与四个高优 P1。全程 TDD + Subagent-Driven,每任务过实现→评审两道门。

## 修复清单

### P0-1 确认重放丢用户身份(commit 5081cd2)
- **问题**:用户确认退款后,`_replay_flow` 在新线程里执行工具,但**没设 current_user**。`auth_enabled=True`(生产默认)时 `owned_order()` 拿到 uid=None → 返回"未找到订单",确认后的退款静默失败,pending 还被清了。
- **根因**:`set_current_user` 只在 `EcomAgent.chat()` 里调,而重放短路不经 chat。
- **修复**:重放前 `set_current_user(agent.user_id)`(无条件,fail-closed);并改走 `agent.tool_manager.execute_tool`(与 ReAct 同路径:MCP 身份透传/结果落盘一致),无 tool_manager 时回退 registry。
- **为何测试没抓到**:conftest 全局 `auth_enabled=False`。新测试**显式开 auth**,这是本批所有确认流测试的红线。

### P0-2 泛化确认词误绑定重放(commit 9e66de1 + 修复 60addf9)
- **问题**:`confirmed = is_confirmation(user_input)`,而 `is_confirmation` 认"可以/好的/是的"。有 pending 时任何含泛化词的短消息都触发重放,不看用户实际说什么。场景:退款 A 单挂起 → agent 问"还要查物流吗" → 用户"可以" → **重放了退款**;或"确认取消 B 单" → 重放的还是 A 单退款。
- **修复**:新增 `confirm_targets_pending(user_input, pending, explicit_confirm)`,确认必须与挂起动作**绑定**——三条信号任一成立才重放:①前端显式 confirm;②消息提到挂起动作的目标 order_id;③强确认词(确认/确定/同意…,**非**泛化"可以/好的")且未提及其它订单号。streaming 的 pending 取用与 granted 都改由此门控,消除泛化词单独放行。
- **评审抓到的绕过(已修)**:大小写敏感——"确认取消 **ord**-…"(小写他单号)绕过 others 检测。修复:归一大小写(text_up/target_up)后再比较,补回归测试。
- **record-only**:空格注入"ORD - 2024…"仍可绕过(罕见输入,独立向量,另开 ticket);"退款吧"对非 refund 挂起语义错配(低危)。

### P1-③ 重放绕过 ToolManager(并入 P0-1 修复)
重放原本直连 registry,MCP 身份透传/结果落盘不生效。现走 tool_manager,与正常 ReAct 工具路径一致。

### P1 限流键改 user_id(commit 60969e3)
- **问题**:`rate_limiter.allow(req.session_id)` 键在客户端可伪造的 session_id,每请求换 id 即绕过 20/min。
- **修复**:键改用 `_resolve_user` 从 token 解出的身份(auth 开时不可伪造;auth 关时退化自报,可接受)。

### P1 意图三面漂移(commit 4e42bec)
- **问题**:`_normal_flow` 返回未覆盖的 `result.intent.value`(英文枚举)喂给 trace.intent,metadata 却发覆盖后的 `intent_out`(投诉→complaint)。看板与 trace 对同一轮意图不一致。
- **修复**:`_normal_flow` 返回 `intent_out`,与 metadata 同变量,trace 对齐。

### P1 reaper 持会话锁跨 LLM(commit 2d25a3d + 加固 4fa4159)
- **问题**:空闲回收 `_consolidate_and_evict` 持会话锁跨多秒 LLM 巩固,用户回来 `/api/chat` 阻塞最长 60s。
- **修复**:巩固/归档移出会话锁,`self._guard` 只护字典读/pop 两个短临界区。
- **权衡(已披露)**:巩固期若有同会话新请求,可能 last-writer-wins 覆盖会话文件——但 reaper 仅在空闲 TTL 后触发,概率极低。
- **顺修**:archive 包 try/except,归档失败不跳过内存回收(名副其实 best-effort)。
