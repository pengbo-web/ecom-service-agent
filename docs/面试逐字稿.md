# 电商客服 Agent 项目 · 面试逐字稿

> 用于面试时口述。每个技术点都配了「能展示的证据」，避免空谈。

---

## 一、30 秒电梯陈述

> 我独立把一个电商客服 Agent 从教学 demo 做成了**真实可上线的在线客服系统**。它以 SQLite 真实业务数据为底座，FastAPI 提供 SSE 流式服务和可嵌入的 Web 客服组件，在核心 Agent 外**叠加了一整套生产能力**:安全护栏、全链路可观测性、人机协作转人工、限流/成本/鉴权加固,并用**评估回归门禁**在每次迭代自动守住线上质量——形成"真实业务数据 → 线上 Trace → 离线评估 → 护栏/转人工兜底"的生产级质量闭环。

关键一点:**这些生产能力全部在服务层以"加法"方式挂载,核心 Agent 逻辑零改动**——可回滚、可开关、每块能独立讲清楚。

---

## 二、整体架构(对着架构图讲)

请求进来后在服务层依次经过:**限流 → 人工接管判断 → 规则快路径 → 成本上限 → 核心 Agent**;Agent 产出回复后经**输出护栏脱敏**再下发。整个过程被**可观测性**记成一条 Trace(含每次 LLM/工具/护栏/转人工的 Span)。

- **核心层**:ReAct + Function Calling + RAG + Memory + Skill(教学项目已有,我复用不改)。
- **真实数据层**:把写死的 mock 换成 SQLite,商品/订单/物流/用户都是真数据,后台改数据对话结果随之变化。
- **服务/治理层**:护栏、可观测、HITL、加固——这是我二次开发的重点。

## 三、逐模块讲(每个都对应一道高频面试题)

### 1. 你怎么防 Prompt Injection / 不泄露敏感信息?——安全护栏
- **输入侧**:规则层拦截"忽略以上指令""开发者模式""泄露系统提示词"等越狱模式,命中即**短路、不调用大模型**,返回安全兜底。
- **输出侧**:对回复里的手机号/身份证/银行卡/邮箱**正则脱敏**,拦截引导站外交易的联系方式。
- **证据**:输入一句注入攻击 → 思考区显示 `🛡️ 护栏[input/block]`、秒回兜底、看板拦截率+1。

### 2. 你怎么知道 Agent 线上表现好不好?——可观测性
- 每次请求一条 **Trace**,内含 Span:每次 LLM 调用(延迟+token)、每次工具调用(延迟+成功与否)、护栏、转人工。
- **难点与设计**:我要求"不动核心",所以用**透明代理包装 OpenAI 客户端**采集 token/延迟,用 W1 就埋好的**事件流**派生工具 Span——埋点和业务逻辑彻底解耦。
- **证据**:看板展示 P50/P95 延迟、token 成本、工具成功率、意图分布;点开单条请求能看到完整调用链。

### 3. Agent 拿不准 / 用户要投诉怎么办?——人机协作
- **升级触发**:低置信度 / 模型判定转人工 / 敏感意图 / **关键词兜底**(用户明说"投诉/维权/曝光"直接转,不依赖模型分类)。
- 生成**交接上下文包**(会话摘要+关键信息+触发原因)进坐席队列;坐席可**一键接管**(Agent 暂停、真人处理),借鉴闲鱼项目的接管开关 + 超时自动回落。
- **证据**:发"我要投诉" → 自动转人工 → 坐席面板出现带上下文的待接管会话 → 接管后 Agent 暂停。

### 4. 改了 prompt 怎么保证没把线上改坏?——评估回归
- 把评估升级为**回归门禁**:黄金集跑分与 baseline 对比,任一指标掉点超容差则 `exit 1`(可接 CI)。
- **闭环亮点**:线上被拦截/转人工/出错的真实对话,一键**回流成新的评估用例**——线上问题自动沉淀为回归测试。
- **证据**:`run_eval --regression` 掉点时非零退出;`reflow_traces` 把问题 Trace 转成用例。

### 5. 公网上线怎么防刷、防烧钱?——生产加固
- **限流**(会话滑窗)、**每日请求预算**(成本兜底)、**管理接口令牌鉴权**。
- **规则/LLM 混合路由**:高频寒暄("你好/谢谢")走规则**秒回**,跳过大模型——省 token、降延迟。
- **证据**:发"你好" 0.04 秒返回、零 token;同会话连发 24 次 → 放行 20、拦截 4(阈值 20/分)。

## 四、可能被深挖的问题 & 应对

- **并发一致性**:同会话请求用锁串行化,避免多请求踩同一 Agent 状态;不同会话隔离各自实例。
- **流式实现**:阻塞式 `chat()` 用"后台线程 + 队列"桥接成 SSE 生成器,前端边收边渲染 ReAct 过程。
- **成本控制**:混合路由规则秒回 + 每日预算 + token 全链路可观测,三管齐下。
- **幻觉**:输出侧可校验回答是否有工具/检索支撑(无支撑可转人工兜底);评估里有 faithfulness 维度。
- **为什么不接真实电商平台**:接第三方平台要逆向私有协议,有合规和封号风险,不是工程正道;我用"自有真实数据层 + 合法 Web 通道"达到同样的"真",且零风险。

## 五、一句话亮点清单(简历 bullet 参考)

- 独立将电商客服 Agent 落地为真实可上线服务:SQLite 真实数据 + FastAPI SSE 流式 + 可嵌入 Web 客服组件。
- 设计可插拔**安全护栏**(注入拦截 + PII 脱敏),线上拦截率可视化。
- 用**透明代理 + 事件流**实现全链路可观测(Trace/Span、延迟/token/成功率),核心零侵入。
- 实现**人机协作**闭环:多信号升级判定 + 交接上下文 + 坐席接管(规则+LLM 混合,兜底可靠)。
- 建**评估回归门禁 + 线上 Trace 回流**,形成质量自守护闭环。
- 生产加固:限流 / 成本预算 / 令牌鉴权 / 规则快路径,Docker 一键部署。
- 设计**多智能体协作**:2 个主 Agent(买家/卖家总控)+ 5 个子画像跑在同一硬化引擎上,经持久化事件总线协作,`correlation_id` 全链路可回溯;买卖两侧工具子集不相交(由测试从注册表派生校验)。
- 全程**不动核心、只做加法**,**1600+ 自动化测试**保障(后端 1616 + 前端 114,默认离线可跑),每模块可开关可回滚。
