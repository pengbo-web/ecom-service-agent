## 退货归因流程

店主提出"退款率为什么高了""退货原因是什么""帮我分析一下售后"时，按以下流程处理。

**产物是一条完整的归因链**：异常现象 → 定位数据 → 根因判断 → 改进建议。

### 第一步：确认异常是否真实存在

调 `anomaly_scan(window_days=7)`。

检查 anomalies 列表中是否有退款相关异常（kind 含 `refund_rate`）。

- **有异常**：记录异常详情（subject、subject_name、value、threshold），继续下一步。
- **无异常**：如实告知店主"近 7 天退款率未超过告警线（当前 X%，告警线 X%），暂无异常需要归因"。
  如果店主坚持要看，可以缩短窗口（window_days=3 或 1）再扫一次，但必须在报告中注明窗口。
- **样本不足**（min_samples 未达）：明确说"样本量不足，无法判定是否异常"。

### 第二步：定位退款集中的商品

调 `product_diagnostics(window_days=7, top_n=10)`。

按退款率从高到低排序，找出退款率超过告警线的商品。对每个高退款商品记录：
- 商品名/SKU
- 退款率（与告警线对比）
- 退款原因 top3（这是归因的核心证据）
- 下单量（判断样本是否充分）

### 第三步：差评佐证

调 `review_insights(window_days=7)`。

从 products 列表中找到与第二步相同的高退款商品，对比差评关键词与退款原因：
- 如果退款原因和差评关键词**高度吻合**（如都指向"尺码偏大"），这是强归因证据。
- 如果不吻合或该商品无差评，退款原因可能来自其他渠道（如直接退款未留评），在报告中注明。

### 第四步：排查服务流程（条件执行）

仅当以下任一条件满足时执行：
- 退款原因中出现"客服态度""回复慢""不处理"等服务类关键词
- `service_quality` 中有 skill 的转人工率 > 40%

调 `service_quality(window_days=7)`，检查是否有特定 skill 的执行异常与退款相关。
若无服务类退款原因，跳过此步。

### 第五步：输出归因报告

```markdown
## 📉 退款归因报告

### 异常确认
- 全店退款率：X%（告警线 X%，超出 X 个百分点）
- 判定窗口：近 7 天
- 异常等级：⚠️ 轻度超线 / 🔴 严重超线（超出告警线 50% 以上为严重）

### 退款集中商品
| 商品 | 下单量 | 退款率 | 退款原因 Top 3 |
|------|--------|--------|----------------|
| 商品A | X 单 | X% ⚠️ | 原因1(X次)、原因2(X次)、原因3(X次) |
| 商品B | X 单 | X% ⚠️ | 原因1(X次)、原因2(X次) |

### 差评佐证
（逐商品对比退款原因与差评关键词）
- **商品A**：退款原因"尺码偏大"(5次) + 差评关键词"尺码"、"偏大" → **强归因**
- **商品B**：退款原因"质量问题"(3次)，无对应差评 → 证据不足，建议抽样回访

### 服务流程排查
（若执行了第四步则输出，否则省略此节）
- 相关 skill 表现：...

### 归因结论
1. **主因**：（如"商品A 尺码标注偏差导致退款集中"）
2. **次因**：（如"商品B 质量反馈但差评数据不足"）

### 改进建议
1. （针对主因的具体动作，如"重新测量商品A 的实际尺码并更新详情页尺码表"）
2. （针对次因的具体动作）
3. （可选：监控建议，如"建议 3 天后复查退款率是否回落"）
```

### 注意事项

- 归因必须有数据支撑（来自工具返回），不能凭假设编造因果链。
- 如果退款率确实正常（未跨线），不要因为店主问"为什么高了"就硬找异常——如实告知"当前未检测到异常"比编一个假归因危害小得多。
- 退款原因与差评关键词的"吻合"判断基于关键词重叠，不需要语义分析，简单匹配即可。
- 建议按优先级排序：主因的建议放第一条，次因放后面。
