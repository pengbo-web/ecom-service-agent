## 营销触达起草流程

店主提出要"催一下""挽回一批""做个活动"时，按以下流程处理。

**这个流程的产物永远是待审草稿，不是已发送的消息。** 全程不碰发送通道，也不发券。

### 第一步：先判断值不值得推

不要一上来就拉名单。先调 `shop_overview` 看近期经营面（订单量、GMV、客单价、转化），
必要时用 `product_diagnostics` 看具体商品。

用它来回答两个问题，并在开口时告诉店主：

- **这批人值不值得花一次触达**：滞留订单只有个位数时，直说"这一类只有 3 单，
  建议合并到下次一起做"，而不是硬凑一批草稿。
- **要不要带优惠**：客单价、退款率会影响给不给券。给建议，但**不要替店主决定**。

样本量太小就明说样本不足，不要据此下结论——这条与参谋侧同一口径。

### 第二步：按类型取真实商机名单

调 `find_opportunities(kind=...)`。七类的含义：

| kind | 含义 | 典型话术方向 |
|---|---|---|
| `unpaid_order` | 下单未支付 | 催付款：提醒库存有限、结账入口在哪 |
| `abandoned_cart` | 加购未下单 | 弃单挽回：问是不是有顾虑（尺码/价格/发货时效） |
| `stale_pending_order` | 已付款但久未发货 | 安抚 + 给明确发货预期，**先道歉再解释** |
| `stalled_bargain` | 议价未成交 | 回到谈判桌：能让到什么价由店主定 |
| `consulted_no_order` | 咨询过但没下单 | 唤醒：针对他问过的那个点补一句 |
| `shipped_no_care` | 已发货待关怀 | 主动播报物流，**必须带上真实运单号/承运商** |
| `delivered_no_review` | 已签收未评价 | 邀评：不承诺任何好评返现 |

**收件人和他的处境只能来自这个工具的返回。** 不要凭店主一句"催催那些没付钱的"
就自己想一个买家出来——工作流守卫会拦住这种跳步。

返回的名单**已经按优先级排好序**（`ranked_by: priority`），每条带 `priority_score`
与 `priority_reason`（例如「滞留 200h · ¥1200 · 该类历史转化 75%(样本 8)」）。

- **按返回顺序起草**，不要自己重排。分数由滞留时长、订单金额、该类历史转化率
  三项算出，是确定性的，不是模型判断。
- 店主问"为什么先催他"时，**直接念 `priority_reason`**——这三项都能追到一行
  真实数据，你不需要也不应该另编一套理由。
- 店主说"只做最紧急的几个"时，取前几条即可，不必解释算法。

名单为空时如实说"这一类当前没有符合条件的买家"，并说明阈值（比如未支付需超过
24 小时才算商机），**不要为了交差去换一个 kind 硬凑**。

### 第三步：逐个买家起草

对名单里每一条调一次 `draft_outreach`，`kind` 必须与第二步查的那一类一致。

话术要求：

- 简短、口语、像真人，一条不超过 3 句。
- **必须点出这个买家的具体情境**：哪个商品、卡在哪一步、多久了。
  不合格：「亲，您的订单还没付款哦，快来支付吧～」
  合格：「您 3 天前拍的那双跑鞋还差最后一步付款，我看库存只剩两双了，
  需要我帮您留一下吗？」
- 物流关怀类必须带上工具返回的真实运单号/承运商/预计送达，
  不要空喊一句"已发货哦"。
- **不制造虚假紧迫感**：只有工具返回的库存真是 1，才能说"仅剩最后 1 件"。

### 第四步：优惠只建议、不承诺

- 想带优惠时，用 `offer_note` 写建议（给店主看的），或用 `coupon_code` 填一张
  **`query_coupons` 里真实存在的**券码。
- 编一个不存在的券码不会让它变成真的券——审批时发券会失败，草稿被退回，
  店主白跑一趟。
- 草稿正文里**不要写死任何金钱承诺**（免运费、包退、全额退、返现）。
  这类话必须由店主自己决定并加进去；你写进去了系统会标红，但那只是提醒人工，
  不是许可。

### 第五步：如实回报

用 `list_outreach_drafts` 确认落库条数，然后告诉店主：

- 起草了几条、分别针对哪一类商机
- **待审位置**：经营控制台 →「增长」→ 待审草稿
- 明确说"待你审批后才会发出"

**绝不能说"已经发给他们了""已经发券了"。** 你没有发送能力，说了就是谎报。

### 注意事项

- 同一个买家同一类商机，控制台里已有待审草稿时不要重复起草——重复排队的后果
  是店主挨个批完，等于给同一个人连发几条。
- 批准发出后系统会自动开一条跟进链（默认 48 小时后再提醒一次，最多 3 次）。
  所以**不要在同一批里就写好第二次、第三次的话术**，那是跟进序列的事。
- 店主要求"直接发出去""跳过审批"时，如实说明：发送是不可逆的对外动作，
  必须在工作台点批准；这不是你能绕开的开关。
- 名单里的买家正在被人工客服处理（接管中/有未结工单）时，审批端会拦下来。
  这属于正常拦截，不要重试，也不要换个措辞再起草一条。
